# SVG Phase 2 Tools

当前实现：扩展工程与 SVG 文件 `[]` 标记（计划第 2、3 步）。SVG 大纲尚未实现。

## 安装与启动

需要 Node.js、npm 和 VSCode 1.85 或更新版本。

1. 在 VSCode 中通过“文件 → 打开文件夹”打开本目录 `vscode-extension`，使本目录成为工作区根目录。
2. 在该目录终端执行 `npm ci` 安装锁定依赖，再执行 `npm run build`。
3. 按 F5，选择 `Run SVG Extension`。调试前自动编译，随后打开“扩展开发宿主”窗口与 `fixtures` 文件夹。
4. 等待窗口启动完成，查看 Explorer 中的文件标记。可在入口 `activate` 中设置断点检查激活。
5. 修改源码后重新启动调试会话，使新编译代码生效。

`vscode` API 由扩展宿主提供；开发时仅安装它的类型声明，无需安装 `vscode` 运行时包。

## 手动验收

- `example.svg` 右侧显示 `[]`。
- `plain.txt`、`folder.svg` 目录及其 README 不显示标记，父目录也不继承标记。
- 在宿主窗口中新建 SVG 文件，或将文本文件重命名为 `.svg`，检查标记；改回 `.txt` 后标记应消失。
- 比较运行前后的文件名和内容，确认没有变化。
- 保存实际运行截图，供后续 A.3 文档使用。若无标记，检查 VSCode 设置 `explorer.decorations.badges` 是否开启，并排查其他文件装饰扩展的干扰。

以上为待在真实 VSCode 窗口完成的人工验收项目，不代表已经获得截图或通过 UI 验收。

## 当前职责划分

- `extension.ts`：组合根，创建并注册提供者，连接文件变化事件，管理资源释放。
- `SvgDecorationProvider`：判断扩展名和文件类型，返回装饰元数据；不存在或无法访问时返回空结果。
- VSCode：加载扩展、调用提供者、渲染 Explorer，扩展不修改文件名称和内容。

此功能通过对象组合给文件视图附加信息，并不包装或替换文件对象，和经典 Decorator 模式仍有差异；完整的模式分析与复用评估留待实践收尾。
